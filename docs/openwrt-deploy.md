# Развёртывание и диагностика OpenWrt

Полноценные продуктовые `apply`, `doctor`, `diff` и `rollback` ещё не реализованы. PoC получает bootstrap и architecture bundle из публичной ветки GitHub; prebuilt bundles и SHA256 sidecars хранятся в `poc/bundles/`. `poc/install.sh --check` выполняет read-only preflight; `--install` при необходимости ставит целевые runtime-пакеты через штатный `apk`/`opkg`, подготавливает файлы, `poc/configure.sh` генерирует проверяемого кандидата, а активация требует typed confirmation. Поддерживается только однорукая схема, где клиентский и upstream трафик использует один LAN-интерфейс. WAN/LAN группы отложены. Helper проверен на выделенной OpenWrt VM и отдельно проходил первичную установку на физическом роутере; R28S пока не проверен.

Для установки требуется интернет/DNS и штатные package feeds OpenWrt. Helper ставит только точечные пакеты, не выполняет общий upgrade и проверяет embedded Tailscale endpoint после установки sing-box. При конфликте чужого mark/table/порта активация отказывается, не отключая существующий стек. На TOP50 helper пока не запускался; перед возможной миграцией старого TPROXY нужен отдельный контролируемый переход.

При загрузке tmpfs пуст: procd должен дождаться появления и проверки требуемых SRS перед запуском sing-box, не блокируя администрирование. Поведение offline зависит от выбранного storage mode; RAM-only не обеспечивает cold boot без источника. Не подменять недоступный VPN прямым выходом. После обновления или reboot проверять работающий путь клиента и отсутствие дублированных nft/ip rules.

Для обследования VM используйте `uci show network.lan`, `cat /proc/sys/kernel/hostname`, `ip -4 addr`, `ip -4 route`, `cat /etc/openwrt_release`, `df -h / /tmp`. Установочная VM может не иметь отдельной команды `hostname`. Сначала обращаться к `docs/test-environment.md`; исторический TOP50 не изменять без отдельного согласования.
