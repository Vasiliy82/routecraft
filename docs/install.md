# Установка RouteCraft PoC

Это руководство описывает PoC для OpenWrt на роутере и в виртуальной машине. Инсталлятор ставит пакеты и файлы, мастер собирает конфигурацию sing-box, а сетевой перехват включается после отдельного подтверждения.

На данный момент RouteCraft не выпускает собственный `.apk` или `.ipk`: используется bootstrap-скрипт и архив `poc/bundles`. В OpenWrt 25.12+ слово APK означает пакет Alpine/OpenWrt, не Android-приложение; предыдущие стабильные ветки используют `ipk` с `opkg`. План отдельного пакета `routecraft` и необязательного `luci-app-routecraft` описан в [обзоре архитектуры](overview.md#поставка-и-пользовательский-интерфейс).

## Предварительные требования

- OpenWrt с доступом к root-shell по SSH или через консоль. Полностью проверен OpenWrt 25.12.6 x86_64; сборки подготовлены для `x86_64/amd64`, `aarch64/arm64` и `armv7`.
- Доступ в интернет с самого роутера: он нужен для OpenWrt package feeds, GitHub, источников GeoSite/GeoIP и вашего VLESS provider.
- В однорукой схеме клиенты и upstream используют один интерфейс. Для раздельных WAN и LAN заранее настройте штатные IPv4 forwarding, LAN-to-WAN firewall и SRCNAT, а также DNS, DHCP и маршруты клиентов. RouteCraft использует эти настройки.
- Перед установкой проверьте интернет с самого роутера. На чистом OpenWrt выполните:

  `uclient-fetch -4 -T 8 -O /dev/null https://raw.githubusercontent.com/Vasiliy82/routecraft/main/poc/install-openwrt.sh`

  Если проверка не проходит, сначала восстановите интернет на роутере. При установленном `curl` можно проверить той же ссылкой: `curl -4 -fIsS --connect-timeout 5 https://raw.githubusercontent.com/Vasiliy82/routecraft/main/poc/install-openwrt.sh`.
- Свободное место на persistent-разделе и в `/tmp`. Перед запуском можно посмотреть его командой `df -h / /tmp`; точный минимум зависит от firmware и пакетов.
- Клиенты должны использовать этот OpenWrt как default gateway. Инсталлятор не меняет настройки DHCP, DNS-рекламу или шлюз клиентских устройств.

Пакеты `sing-box`, `curl`, `ca-bundle`, `coreutils-stty`, `ip-full`, `nftables-json` и `kmod-nft-tproxy` ставятся штатными feeds по необходимости. OpenWrt 25.12 и новее использует `apk`, старые выпуски — `opkg` ([руководство OpenWrt](https://openwrt.org/docs/guide-user/additional-software/managing_packages)). Код содержит оба варианта, но end-to-end установка проверена на `apk` в OpenWrt 25.12.6. Установщик обновляет индекс пакетов и добавляет только отсутствующие зависимости; полный `apk upgrade`/`opkg upgrade` не запускается. После установки sing-box проверяется поддержка embedded Tailscale endpoint и nftables TPROXY.

Если на роутере уже работает другой sing-box/TPROXY, занят mark `0x81`, table `100` или порт `12345`, установщик остановит активацию, не выключая чужую конфигурацию. Сначала потребуется отдельный контролируемый переход. На известных устройствах состояние до установки может отличаться от чистой VM.

## Установка из публичного репозитория

Файлы RouteCraft устанавливаются в `/etc/routecraft`. После подтверждённой активации OpenWrt управляет службой `routecraft` через `/etc/init.d/routecraft`. Архивы называются `routecraft-openwrt-<arch>.tar.gz`.

### Файлы секретов

Мастер ищет на роутере два файла:

| Стандартный путь | Содержимое |
| --- | --- |
| `/root/routecraft-config/tailscale-pre-auth-key` | Ключ предварительной авторизации встроенного Tailscale в sing-box |
| `/root/routecraft-config/vless-subscription-url` | URL VLESS-подписки |

Запишите в каждый файл одно непустое значение. Используйте владельца `root`, права `0700` для каталога и `0600` для файлов. Мастер использует доступный файл без запроса и без вывода значения. При отсутствии файла мастер запрашивает значение с отключённым эхом. Вход системного Tailscale использует отдельный ключ.

### Запуск мастера

Для перехода со старой или стендовой установки сохраните её каталог, init-скрипт и настройки сети. Проведите переход в окно обслуживания с проверенным доступом к консоли или по системному Tailscale. Остановите и отключите автозапуск старой службы перед активацией новой. Установщик использует новый каталог, поэтому перенос существующей политики, состояния и секретов выполняется отдельно. Кандидат sing-box нужно пересобрать, чтобы его абсолютные пути указывали на новый каталог. При откате остановите новую службу, восстановите конфигурацию и запустите прежнюю.

Сначала подключитесь к OpenWrt по SSH под `root`. На виртуальной машине откройте root-shell через консоль гипервизора или SSH. Репозиторий содержит готовые bundles amd64, arm64 и armv7 вместе с SHA256 sidecar в `poc/bundles/`.

Запустите bootstrap:

```sh
uclient-fetch -4 -O /tmp/routecraft-install.sh https://raw.githubusercontent.com/Vasiliy82/routecraft/main/poc/install-openwrt.sh && sh /tmp/routecraft-install.sh
```

Bootstrap определит `uname -m`, скачает подходящий архив и sidecar прямо из репозитория, проверит SHA256, установит недостающие пакеты из настроенных OpenWrt feeds и запустит мастер настройки:

1. Покажет доступные сетевые устройства, исключая порты bridge и неподдерживаемые виртуальные устройства, и предложит выбрать WAN и LAN. Для однорукой схемы выберите одно устройство в обоих запросах. Для классической схемы выберите устройство действующего IPv4 default route как WAN и клиентское устройство как LAN. Затем проверьте предложенные подсеть и DNS.
2. Спросит об отключении dnsmasq rebind protection (по умолчанию — да). При подготовке кандидата настройки не меняются; при подтверждённой активации делается резервная копия и выполняется перезапуск dnsmasq. Если есть незакоммиченные UCI-изменения DHCP, активация откажет.
3. При первой установке предложит установить отсутствующий Tailscale. Если локальный клиент показывает доступные online Exit Node, мастер предложит выбрать узел, затем спросит control URL и pre-auth key для отдельной identity sing-box. Без пригодного узла или при отказе начальное правило Tailscale исключается. URL VLESS-подписки необязателен при первой установке: при отсутствии или неудачной загрузке мастер сообщает об исключении начального правила подписки. У действующей установки пустая или неработающая подписка вызывает отказ без изменения активной политики. Для только что установленного системного клиента мастер может запросить отдельный ключ и подключить его к Tailscale или Headscale; создание системной identity подтверждается отдельно и сохраняется при отмене активации RouteCraft. При наличии старого состояния автоматическое подключение не выполняется. Существующую identity мастер не копирует. Секреты вводятся без отображения и сохраняются с ограниченными правами.
4. Скачает используемые SRS, соберёт кандидат конфигурации и проверит его командой `sing-box check`.
5. Предложит активацию. Для запуска нужно ответить `y`, затем ввести `ACTIVATE`.

Активация включает policy routing, nftables TPROXY на LAN и procd-службу RouteCraft. В однорукой схеме она также включает IPv4 forwarding и SRCNAT. Инсталлятор не меняет клиентский gateway: установите LAN-адрес роутера как default gateway для тестового клиента отдельно. Сохраните независимый доступ к роутеру на время настройки.

Мастер определяет интерфейс из UCI, подсеть — из маршрутов выбранного интерфейса, DNS — из UCI или, если там нет DNS, предлагает адрес текущего шлюза как предположение. При отсутствии значения нужно ввести его вручную. Проверьте подсказки: адрес шлюза не обязательно является DNS-сервером.

### Топология виртуальной машины

Для однорукой схемы подключите OpenWrt VM и клиентскую VM к одному виртуальному сегменту с доступным upstream gateway. Клиент использует адрес OpenWrt VM как default gateway.

Для классической схемы подключите WAN OpenWrt VM к upstream-сегменту, а LAN и клиентскую VM к отдельному внутреннему сегменту. Проверьте, что клиент получил адрес, DNS и шлюз из LAN. Сохраните доступ к консоли гипервизора на время настройки.

## Обновление bundles разработчиками

При изменении PoC разработчик запускает `make package-openwrt` и коммитит обновлённые архивы и SHA256 sidecars из `poc/bundles/`. Пользователю вручную собирать или копировать bundle не нужно.

## Быстрая проверка

С тестового клиента, которому отдельно назначен RouteCraft как gateway:

```sh
curl -4 https://2ip.io/                              # Tailscale Exit Node
curl -4 https://ifconfig.me/                         # VLESS
curl -4 https://icanhazip.com/                       # direct
curl -4 -I --max-time 10 https://theuselessweb.com/  # ожидается отказ
```

Внешние IP могут меняться вместе с выходным узлом. На самом OpenWrt статус процесса смотрите командой `service routecraft status`, журнал — `logread | grep sing-box`.

Сам по себе статус службы не доказывает маршрутизацию: проверяйте ответы клиента и выбранный выход по журналу. Правило перехвата использует только входящий LAN-интерфейс и не меняет системный `src_valid_mark`; работу конкретных VPN после установки также нужно подтвердить запросами.

## Границы текущего PoC

- Перехватывается IPv4 TCP/UDP; это не готовый полнофункциональный маршрутизатор для IPv6/ICMP.
- Нет LuCI, обновления VLESS-подписки по расписанию и автоматического обновления GeoSite/GeoIP.
- Готовые bundles хранятся в репозитории; при изменении PoC разработчики пересобирают их командой `make package-openwrt` и коммитят вместе с исходным кодом.
- RouteCraft не предоставляет VPN-аккаунт и не гарантирует доступность сторонних сайтов. Туннели и выходные IP принадлежат выбранному вами провайдеру/серверу.
