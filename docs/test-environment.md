# Тестовый контур

PoC проверяется на двух изолированных виртуальных машинах OpenWrt: одна работает как однорукий gateway, вторая — как клиент. Верифицированная версия для этой схемы — OpenWrt 25.12.6 x86_64. Для каждого клиентского запроса проверяется выбранный выход и результат sing-box/nftables, а не только статус службы.

Тестовые ключи, URL подписок и способы доступа намеренно не перечисляются в публичной документации. Техническая топология стенда описывается ниже; её локальные IP не являются адресами выхода в интернет. Для повторения тестов используйте собственный Headscale Exit Node, VLESS subscription и изолированную L2-сеть; не подставляйте production credentials в CI или публичные отчёты.

Контрольная политика PoC: `2ip.io` → Tailscale Exit Node; `ifconfig.me` → VLESS; `icanhazip.com` → direct; `theuselessweb.com` → block. Внешние IP адреса зависят от выбранных выходов и не являются ожидаемыми фиксированными значениями.

## TOP50 / OpenWrt `.253`

Снимок диагностики 2026-11-14: OpenWrt 25.12.6 `x86_64`, `br-lan` = `192.168.80.253/24`, upstream gateway/DNS = `192.168.80.254`. Изначально в UCI не были заданы ни default gateway, ни upstream DNS; `resolv.conf` указывал только на локальные stub-адреса. Поэтому роутер не мог сам скачать bootstrap, хотя соседний `.254` отвечал на ping. Добавлены `network.lan.gateway=192.168.80.254` и `network.lan.dns=192.168.80.254` и сохранены в UCI.

На `.253` выполнен `install.sh --install`: установлены `sing-box 1.13.21`, `curl`, `ip-full`, `kmod-nf-tproxy` и `kmod-nft-tproxy`; после установки осталось около 23.6 MiB на root-разделе. Повторный `install.sh --check` прошёл, TPROXY kernel expression доступен. RouteCraft не активирован: его служба, policy table и nftables правила не создавались. Самостоятельный публичный GitHub Release на момент проверки ещё не опубликован; для проверки использовался локальный bundle и его SHA256.
