Обе VM имеют ядро `6.12.112`, релиз `r33311-981c978eff` и примерно 492,7 МиБ tmpfs `/tmp`. Первоначальный размер ext4 `/` составлял около 98,3 МиБ; 12.11.2026 пользователь увеличил диски в ESXi, после чего GPT-раздел `/dev/sda2` и файловая система каждой VM расширены на весь доступный диск. `df -h /` после загрузки показывает 7,9 ГиБ всего и 7,8 ГиБ свободно. На обеих доступны `apk`, `ip-full` и `curl`; на VM1 установлен `sing-box` 1.13.21 и модуль nft TPROXY.

Начало `/dev/sda2` сохранено на секторе 33280, PARTUUID остался `011cbbbd-1913-b25c-1f6f-606edfea6a02`. После автономного расширения и исправления метаданных окончательный `e2fsck -f -n` на обеих VM завершился с кодом 0. Обычная конфигурация GRUB восстановлена; временная среда удалена с VM. Локальные журналы, копии исходного GRUB и GPT-метаданные находятся в `archive/disk-backups/`, который не отслеживается Git. Для VM1 исходная первичная GPT сохранена непосредственно с неё; отдельная резервная GPT в её каталоге скопирована с VM2 после проверки идентичности первичных GPT и явно так названа.

На обеих VM настроен `br-lan` `/24` и UCI DNS через `192.168.80.254`. VM1 использует маршрут по умолчанию через `.254`; на VM2 UCI сохраняет VM1 `.241` как шлюз по умолчанию. Активный PoC на VM1 хранится в `/etc/routecraft-poc`, его конфигурацию sing-box запускает служба procd `/etc/init.d/routecraft-poc` (автозапуск включён). На VM2 постоянный gateway задан в `/etc/config/network`. Перезагрузка обеих VM проверена. Обновление VLESS-подписки и геоданных автоматически не выполняется: при старте используется сохранённый проверенный снимок; `poc/start.sh` вручную загружает и собирает новый.

Вход: `ssh root@192.168.80.241` или `ssh root@192.168.80.242`. Использовалась доступная SSH-аутентификация текущего окружения; пароль не предоставлялся. Если VM не отвечает после перезагрузки, пользователь может восстановить снапшот. Указанные VM — тестовые; исторический TOP50 `.253` не изменять без отдельного согласования.
