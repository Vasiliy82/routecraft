## Concrete Steps

Команды выполняются из `D:/Projects/github.com/vasiliy82/routecraft` в PowerShell после разрешения пользователя. Перечитать исходные документы перед архивированием, проверить состав с `Get-ChildItem -Force` и сохранить изменения документов. Команды не должны удалять исходники или перезаписывать уже существующие файлы.

Для VM1 подключиться `ssh root@192.168.80.241`; убедившись, что это нужная VM, выполнить в её shell:

    uci set system.@system[0].hostname='routecraft-dev01'
    uci set network.lan.proto='static'
    uci set network.lan.ipaddr='192.168.80.241'
    uci set network.lan.netmask='255.255.255.0'
    uci set network.lan.gateway='192.168.80.254'
    uci -q delete network.lan.dns
    uci add_list network.lan.dns='192.168.80.254'
    uci commit system
    uci commit network
    reboot

Для VM2 подключиться `ssh root@192.168.80.242`, применить те же команды, заменив hostname на `routecraft-test01`, IP на `192.168.80.242`, затем выполнить оба commit и reboot. После каждого reboot подключиться снова и сравнить вывод `hostname`, `uci show network.lan`, `ip -4 addr`, `ip -4 route`, `cat /etc/os-release` и `df -h` с ожидаемыми параметрами. Убедиться, что имя и IP соответствуют именно проверяемой VM. Команды настройки могут оборвать SSH; при отсутствии повторного входа не повторять команды вслепую.

После выполнения подготовительного этапа в корне выполнить `git init`, `git check-ignore -v archive/source-handoff/AGENTS.draft.md`, `git status --short --untracked-files=all`, затем `git add AGENTS.md docs .gitignore` и проверить `git diff --cached --stat` и `git diff --cached`. Если Git не настроен или операция заблокирована, сообщить конкретную ошибку; не подменять личность автора произвольными данными.

## Idempotence and Recovery

До перемещения файлов сохранить их SHA256 и не заменять существующие назначения; после переноса проверить хеши. Игнорирование архива не является резервной копией Git. Настройка UCI повторяема, но reboot и смена IP способны прервать доступ: работать по одной VM и использовать доступные пользователю снапшоты для восстановления. Не изменять TOP50. Перед транзакционными сетевыми изменениями продукта сохранять совместимое рабочее состояние и проверять полный rollback; обновления данных публиковать только целым проверенным поколением. При недоступности upstream сохранять предыдущий валидный набор и не делать неявный DIRECT fallback.
