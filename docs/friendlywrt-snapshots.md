# Снапшоты FriendlyWrt на NanoPi R28S

Три shell-скрипта для исследованной FriendlyWrt 25.12.5. Они находят `userdata` по аргументу `data=`, а `opt` по GPT-имени на том же MMC/SD. Хранилище монтируется в `/persistent`. Установка работает на штатном загрузочном образе.

## Установка

Скопируйте `snapshot/setup.sh`, `snapshot/after-firstboot.sh` и `snapshot/snapshotctl.sh` в один каталог на роутере. Выполните из него от root:

```sh
sh setup.sh
snapshotctl help
```

Установщик создаёт `/persistent/bin` и `/persistent/snapshots`, настраивает монтирование по UUID через UCI и создаёт ссылку `/usr/bin/snapshotctl` на `/persistent/bin/snapshotctl`.

## Использование

```sh
snapshotctl create golden
snapshotctl list
snapshotctl restore golden
snapshotctl delete golden
```

`create` копирует раздел в `/persistent/snapshots/NAME.img`. На исходном устройстве каждый образ занимает около 1,5 ГиБ. Для переноса скопируйте `.img` обычным `scp`. Образы содержат ключи и пароли. Храните их с правами `0600` в закрытом каталоге.

`restore` проверяет размер файла, записывает его через `dd conv=fsync` прямо в работающий `userdata` и при успехе сразу вызывает `reboot -f`. Если `dd` завершится с ошибкой, команда сообщит об этом. В этот момент раздел уже может быть частично перезаписан.

И создание, и восстановление работают с активным ext4. Запись файлов во время копирования может сделать снимок несогласованным, а быстрая перезагрузка после восстановления сокращает окно, в котором активная система продолжает писать в раздел, но целостность не гарантирует. Для восстановления после сбоя держите копию образа на другом носителе и доступ к консоли. При необходимости запишите копию из среды обслуживания в проверенный несмонтированный раздел с GPT-именем `userdata`.

## После Factory Reset

Выполните штатное `firstboot -y && reboot`. После загрузки скопируйте `after-firstboot.sh` на роутер, запустите `sh after-firstboot.sh` и выполните `snapshotctl list`. Сохранённая копия этого же скрипта лежит в `/persistent/bin/after-firstboot.sh`, если `opt` уже смонтирован вручную.

`opt` можно использовать и для других данных, например `/persistent/docker`. Эти данные имеют собственный жизненный цикл и не входят в образ `userdata`.

## Проверка

На R28S ранее прочитаны разметка и штатный код `firstboot`, который при обычном сбросе очищает `userdata`. Локально проверены синтаксис трёх скриптов, копирование и побайтовое восстановление тестового файла, вызов заглушки перезагрузки и удаление. Полный цикл с записью и перезагрузкой на R28S ещё не проверен.
