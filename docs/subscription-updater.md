# ТЗ на обновление VPN-подписки RouteCraft

## Назначение

Утилита `/etc/routecraft/subscription.sh` работает под OpenWrt `sh`. Она хранит URL VPN-подписки, проверяет доступные узлы и обновляет выход `vpn-sub` действующего sing-box. Реализация использует shell и штатные утилиты OpenWrt. Совместимость с ядром определяется установленным sing-box.

## Команды и состояние

- `subscription.sh set url URL` задаёт HTTP/HTTPS URL. `subscription.sh set url --stdin` читает его из stdin. Команда проверяет синтаксис и сохраняет адрес без обращения к провайдеру или перезапуска сервиса.
- `subscription.sh get url` выдаёт сохранённый URL по явному запросу. `subscription.sh set hwid ID` задаёт уже зарегистрированный идентификатор. При его отсутствии UUID v4 создаётся при первой загрузке и затем используется повторно.
- `subscription.sh check` загружает подписку, проверяет все узлы и показывает выбранный номер, не применяя конфигурацию. `subscription.sh update` выполняет те же пробы и автоматически применяет результат при изменении выхода.
- Настройки, последний результат загрузки и последний применённый узел хранятся в `/etc/routecraft/subscription/` с правами 0700 у каталога и 0600 у файлов. URL, URI, UUID и сырые ответы доступны из закрытого состояния. Обычный вывод содержит номер узла, протокол, результат и обнаруженный IP.
- В терминале `check` и `update` показывают ход загрузки, номер узла из общего числа, его подпись и результат полного запроса. Внешний IP выводится при успехе. При применении выводятся этапы проверки кандидата, перезапуска и проверки живого HTTPS. Подписи берутся из URI, поля `ps` VMess и тега JSON. Смена подписи обновляет сохранённые сведения об узле без перезапуска sing-box.

## Проверка и выбор

Запрос использует постоянный HWID и правила загрузки существующего shell-PoC. Для каждого узла с поддерживаемым форматом выполняется `sing-box check`, затем HTTPS-запрос к сервису определения внешнего IPv4 через временный loopback SOCKS-вход. Sing-box разрешает имя HTTPS-сервиса по DoH через проверяемый outbound и использует полученный адрес для HTTPS через тот же outbound. DNS, установка соединения и получение HTTP-ответа используют общий лимит в одну секунду. Успех требует ответа с корректным IPv4. Проверяются все узлы в порядке выдачи провайдера. Первый подходящий узел становится кандидатом. При ошибке получения или отсутствии подходящих узлов активный выход сохраняется.

## Применение

- Утилита берёт ту же блокировку `.update.lock`, которую используют установщик и сборщик, на время чтения и изменения активного конфига.
- В `sing-box.json` сохраняются политика, DNS, Tailscale и прочие выходы. Меняется только `vpn-sub` и удаляются прежние узлы подписки, на которые ссылался её selector. В активном конфиге остаётся один выход подписки с тегом `vpn-sub`.
- Сравнение опирается на конфигурацию фактического выхода и игнорирует форматирование JSON, имя узла и IP, полученный при тестировании. При старом selector первая запись утилиты переводит его на один выход подписки. Последующие обновления с тем же выходом обходятся без записи конфига и перезапуска.
- Для нового выхода кандидат проходит `sing-box check`. Утилита сохраняет предыдущую конфигурацию, атомарно заменяет файл и перезапускает сервис RouteCraft, который управляет sing-box. После запуска проверяются состояние сервиса и реальный HTTPS через его локальный VPN-вход. При сбое утилита восстанавливает старый файл и перезапускает сервис с ним. Применённый узел сохраняется после успешной проверки.

## Расписание и приёмка

Дневной запуск задаётся записью OpenWrt cron для команды `subscription.sh update`. Ручной запуск и cron используют общую блокировку. Приёмка проводится на выделенном OpenWrt-роутере. Проверки покрывают чтение и запись URL, порядок и полноту проб, вывод IP, однократный переход со selector, отсутствие рестарта при неизменном выходе, сохранение старой конфигурации при ошибке проверки и откат при ошибке запуска. После реального применения проверяются трафик через сервис и доступ к роутеру по системному Tailscale.
