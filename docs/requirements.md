# Техническое задание RouteCraft

Статус: требования к будущей реализации, а не перечень уже работающих функций. Приоритет: прямые указания пользователя, затем уточнения handoff, затем исходное ТЗ. Реальное тестирование каждого компонента фиксируется отдельно.

## Назначение и функциональные границы

Система должна позволять редактировать политику и применять её без ручной правки конфигурации sing-box и nftables. Шлюз обрабатывает IPv4 TCP и UDP для всех клиентов, выбравших его шлюзом, включая one-arm топологию, где вход и выход находятся на одном интерфейсе. Остальные устройства локальной сети сохраняют прежний путь. IPv6 forwarding, ICMP, TUN и QoS не входят в первую версию; LuCI поставляется отдельным этапом. Целевая исходная платформа — OpenWrt 25.12.6 x86_64 и sing-box 1.13.21; фактическую совместимость необходимо подтвердить.

Входная политика определяется в `docs/policy-schema.md`: правила сравниваются по порядку, первое совпадение выбирает именованный выход, фильтры одного правила — альтернативы, последнее правило без фильтра обязательно. Локальные и служебные сети исключаются до пользовательской политики. Пользовательская целевая политика: категории openai, cursor, anthropic и точное имя 2ip.io через конкретный Exit Node; категории ru-blocked, youtube, telegram и whatsapp из примера — через VLESS; default — direct. Подробные типы фильтров и все категории приведены в схеме. Не считать наличие категорий проверенным.

## Требования по компонентам

**FR-01 — геоданные.** Полный индекс опубликованных GeoSite и GeoIP, с именем источника, ревизией, checksum, временем и путём; независимые пространства имён, явно определённый приоритет overlays, лицензионная атрибуция. Проверять актуальный upstream и валидность SRS, а не только сигнатуру первых байтов. Все загрузки staged, публикация цельными версиями, при ошибках сохраняется последнее валидное поколение. Доступ к полному каталогу и файловым данным офлайн зависит от режима хранения; три режима и их гарантии описаны в архитектуре. Периодическая проверка без изменений не должна записывать GeoDB на microSD.

**FR-02 — policy compiler.** Строгая схема, позиции ошибок, уникальность имен, корректность IP/доменов/портов и известных категорий и выходов. `validate` и `compile` не меняют сеть; компиляция детерминирована, включает только используемые локальные SRS, сохраняет порядок и OR, не использует устаревшие поля GeoIP/GeoSite sing-box. Sniffing до доменной маршрутизации; IP-only работает без домена. Учитывать схему фиксированной версии sing-box, включая `route.default_domain_resolver`. `explain` показывает индекс и имя правила, фильтр, версию GeoDB и выход, честно отмечает ограничения и не подменяет фактический сетевой замер.

**FR-03 — DNS.** Слушатель на адресе шлюза TCP/UDP 53, доменные правила с тем же порядком, независимый bootstrap и разрешённый DNS upstream для каждого выхода. Исключения для внутренних зон, reverse DNS и Tailscale/MagicDNS, в том числе `100.100.100.100`; отсутствие утечек и циклов. GeoIP не определяется по одному DNS-имени. При shared IP, ECH и собственном DoH клиента ожидаемая точность ограничена. Принудительный перехват DNS в сети — только явная настройка.

**FR-04 — шлюз ОС.** Один и тот же интерфейс может обслуживать ingress и egress; TPROXY доставляет TCP/UDP локальному listener, принадлежащие приложению nftables и policy routing должны иметь идентифицируемое владение, обновляться без дубликатов и удаляться без затрагивания чужих правил. Исключаются LAN, multicast, link-local, защищённые IP, управляющий и собственный трафик транспорта. Проверяется SNAT и обратный путь. Адрес конкретного тестового клиента не может быть обязательным условием. IP next-hop должен быть достижим и проверен реальным трафиком; Tailscale IP нельзя автоматически считать Linux next-hop.

**FR-05 — подписка и выходы.** Интеграция VLESS/REALITY через provider, обновление узлов без удаления DNS, политик, endpoint и rule set; предыдущий рабочий набор сохраняется при сбое. Один контроллер владеет общей конфигурацией и общим lock, вместо конкурентного писателя `vless-sync.py`. Никакого неявного direct fallback. Системная Tailscale identity администрирования отделена от embedded identity для Exit Node; не менять системный default exit node ради пользовательских правил. Реальный Exit Node требует собственной e2e-проверки.

**FR-06 — интерфейс и диагностика.** CLI `routecraft init`, `db update/status/list`, `validate`, `compile --output`, `diff`, `apply`, `rollback`, `status`, `explain`, `doctor`; при развитии `storage status`, `tailscale status`, `trace`. Диагностика различает ingress, nft, policy route, socket, DNS и выбранный выход. При временной диагностической nft-правке обеспечить очистку при ошибке и отмене. LuCI вызывает те же операции контроллера и отображает ошибки, план изменений и состояние.

**FR-07 — применение и восстановление.** Под общим lock снимок состояния, генерация кандидата, проверка ссылок/SRS, `sing-box check`, nft syntax и реальный изолированный startup, переключение, положительные health-проверки, commit или rollback конфигурации, DNS, nft, ip rules/routes и процесса. Неизменное повторное применение — no-op. При невозможности изоляции — явно обозначенный maintenance mode и проверяемый откат. Секретные runtime-файлы должны иметь корректные права, в частности 0600.

**FR-08 — загрузка и ограниченные записи.** Persistent identity сохраняется; runtime-логи и активные SRS по возможности в tmpfs. procd не запускает sing-box до подготовки и проверки требуемых SRS, retry и таймауты не должны блокировать управление. Реальные записи состояния Tailscale и логов измеряются. Offline cold boot допускается только при наличии данных выбранного режима, иначе отказ без утечки в direct.

## Приёмочные сценарии

| ID | Проверяемое поведение |
|---|---|
| AT-01 | Пересечение vpn-static и direct выбирает первое правило. |
| AT-02 | Перестановка правил меняет результат без правки исходных категорий. |
| AT-03 | YouTube и Telegram идут через подписку при наличии категорий. |
| AT-04 | IP-only геокатегория или CIDR выбирает маршрут без DNS. |
| AT-05 | Неизвестное назначение использует единственный default. |
| AT-06 | Неизвестная категория даёт ошибку без изменения активного состояния. |
| AT-07 | Неизвестный выход даёт ошибку без перехода на direct. |
| AT-08 | 404, таймаут и повреждённый SRS сохраняют last-known-good. |
| AT-09 | Повторный apply не создаёт дубликатов и лишних перезапусков. |
| AT-10 | Обновление VLESS сохраняет политику и DNS. |
| AT-11 | Bootstrap и MagicDNS работают без циклов и утечек. |
| AT-12 | Сбой startup кандидата возвращает рабочий DNS и выход. |
| AT-13 | One-arm обслуживает двух клиентов без фиксированного IP. |
| AT-14 | Недоступный IP gateway обнаруживается без скрытого direct. |
| AT-15 | Explain совпадает с наблюдаемым путём контролируемого fixture. |
| AT-16 | После reboot восстанавливаются nft, IP rules, DNS и сервис. |
| AT-17 | Для одного TCP-запроса видны вход, nft, inbound, выход и ответ; отказ локализуется. |
| AT-18 | Два клиента с выбранным шлюзом работают, остальные и управление не затронуты. |
| AT-19 | DNS TCP/UDP/DoH через реальный embedded Exit Node, таймауты и AAAA проверены отдельно. |
| AT-20 | Управляющая Tailscale identity работает при отказе отдельной Exit identity. |
| AT-21 | Cold boot и отсутствие сети соответствуют выбранному storage mode без direct leakage. |
| AT-22 | Периодический опрос без изменений не записывает GeoDB на flash. |
| AT-23 | Одновременные обновления подписки, GeoDB и apply сохраняют активное состояние. |
| AT-24 | Частичная загрузка набора не публикует смешанную версию. |
| AT-25 | Отсутствующие ru-blocked/cursor и битый SRS дают понятную ошибку с provenance. |
| AT-26 | Измерены записи persistent Tailscale state и логов при idle и смене состояния. |

Набор тестов должен включать unit/contract без root и сети, Linux netns E2E с CAP_NET_ADMIN, тесты обновлений с локальным mock upstream и явные реальные smoke-тесты на VM. `sing-box check` и работа процесса не являются доказательством клиентского трафика. Отдельно фиксировать tests passed, skipped и ограничения; реальные сценарии нельзя заменять mock и выдавать за выполненные.
